# 전처리 최적화 개요

## 문제 정의

로컬 LLM으로 긴 영상을 분석할 때 발생하는 두 가지 핵심 문제:

1. **처리 시간**: 영상 전체를 프레임 단위로 처리하면 연산량이 영상 길이에 선형 이상으로 증가
2. **컨텍스트 윈도우 낭비**: 원본에 가까운 데이터(프레임 이미지, 전체 전사문)를 그대로 넣으면
   토큰이 폭증하고, 컨텍스트 중간 정보의 회수율이 떨어져(lost-in-the-middle) 정확도 저하

## 핵심 전략

> **"LLM에 도달하기 전에 정보를 최대한 압축·구조화하고, 질의 시점에는 관련 구간만 선별해서 넣는다."**

이를 위해 전처리를 3개 축으로 분리한다:

| 축 | 입력 | 출력 (LLM 입력 후보) | 문서 |
|---|---|---|---|
| 영상 | 프레임 시퀀스 | 씬 단위 캡션·키프레임·시각 이벤트 | [01-video.md](./01-video.md) |
| 음성 | 오디오 트랙 | 타임스탬프 전사문·화자 정보·오디오 이벤트 | [02-audio.md](./02-audio.md) |
| 메타데이터 | 컨테이너·부가 정보 | 시간축 인덱스·챕터·내장 자막 | [03-metadata.md](./03-metadata.md) |

세 축의 출력은 **공통 타임라인**으로 병합되고, 질의 시 중요 구간을 검색·선별하여
컨텍스트를 조립한다 → [04-integration.md](./04-integration.md)

## 설계 원칙

1. **조기 압축 (Early Reduction)**: 파이프라인 앞단에서 중복·무의미 데이터를 제거할수록
   뒷단 전체의 비용이 줄어든다. (예: VAD로 무음 제거 → STT 대상 축소)
2. **텍스트화 우선**: 이미지·오디오를 가능한 한 텍스트(캡션, 전사, 이벤트 태그)로 변환.
   텍스트는 이미지 토큰 대비 수십 배 압축 효과가 있고 검색·인덱싱이 쉽다.
3. **계층적 요약 (Hierarchical Summarization)**: 프레임→샷→씬→챕터→전체 순으로
   상향 요약을 미리 생성. 질의 난이도에 따라 적절한 계층만 컨텍스트에 투입.
4. **지연 처리 (Lazy / 2-Pass)**: 비싼 연산(OCR, 객체 검출, 고해상도 캡셔닝)은
   전 구간에 돌리지 않고, 1차 패스에서 후보 구간을 좁힌 뒤 필요한 곳에만 적용.
5. **질의 시점 선별 (Retrieval)**: 전처리 산출물은 전부 인덱싱해 두고,
   실제 LLM 입력은 질의와의 관련도 기준 top-k 구간만 사용.

```
원본 영상
   ↓
입력 정규화·디멀티플렉싱
   ├─ 영상 처리 파이프라인      ← 01-video.md
   ├─ 음성 처리 파이프라인      ← 02-audio.md
   └─ 메타데이터·시간축 인덱스  ← 03-metadata.md
          ↓
멀티모달 타임라인 생성          ← 04-integration.md
          ↓
중요 구간 검색·선별             ← 04-integration.md
          ↓
LLM 입력 컨텍스트 조립          ← 04-integration.md
          ↓
요약·질의응답·이벤트 분석
```
