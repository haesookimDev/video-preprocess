# 타임라인 통합·구간 선별·컨텍스트 조립

목표: 세 파이프라인의 산출물을 병합한 타임라인에서 **질의에 필요한 최소한의 구간만**
골라, 토큰 예산 안에서 정확도가 최대가 되도록 LLM 입력을 조립한다.

## 1. 멀티모달 타임라인 병합

- 씬(video)을 **기본 골격**으로 삼고, 전사 턴·오디오 이벤트를 겹침 기반으로 씬에 귀속
- 씬별 통합 뷰 생성. 여러 keyframe caption은 frame metadata 배열로 보존하고 검색용 시각 줄은
  시간 순서의 중복 caption을 제거한 하나의 호환 summary로 만든다:

```
[Scene 12 | 12:34–13:11 | Chapter 3 "Q3 계획"]
  시각: 강의실에서 발표자가 슬라이드 'Q3 Roadmap'을 가리키며 설명 (OCR: Q3 Roadmap, Milestone 2)
  발화: (SPK_2) 3분기 로드맵에서 마일스톤 2가 가장 리스크가 큽니다.
  이벤트: 박수 (13:00)
```

- 이 **씬 카드(scene card)** 텍스트가 검색·조립의 기본 단위가 된다

## 2. 중요 구간 검색·선별 (Retrieval)

### 질의가 있는 경우 (질의응답)

하이브리드 검색으로 top-k 씬 선택:

1. **키워드 검색** (FTS) + **의미 검색** (임베딩) 점수 결합 (RRF 등 간단한 랭크 융합)
2. 엔티티 테이블 매칭 시 해당 구간 가산점
3. 선택된 씬의 **앞뒤 인접 씬**을 후보에 추가 (문맥 연속성)
4. 필요 시 소형 LLM으로 후보 재랭킹 (candidates 20 → final 5 수준)

### 질의가 없는 경우 (전체 요약·이벤트 분석)

- 사전 계산된 saliency 점수 상위 구간 + 챕터별 균등 커버리지 보장
  (점수만 따르면 특정 구간 편중 → 챕터당 최소 1개 씬 강제 포함)

## 3. 컨텍스트 조립 (토큰 예산 관리)

컨텍스트를 계층 구조로 조립하고, 각 층에 토큰 예산을 배분한다:

```
[전체 요약]           — 항상 포함, 예산의 ~10%  (전역 맥락 제공)
[챕터 목차]           — 항상 포함, ~5%          (시간 구조 제공)
[선별된 씬 카드 원문]  — top-k, ~70%             (근거 데이터)
[질의 관련 엔티티 정보] — 해당 시, ~10%
[여유분]              — ~5%
```

- **원문 우선 원칙**: 선별된 구간은 요약이 아닌 씬 카드 원문(전사 원문 포함)을 넣는다 —
  인용·수치·고유명사 정확성은 원문에서만 보장됨
- **예산 초과 시 강등 순서**: 키프레임 이미지 제거 → 낮은 순위 씬 카드를 씬 요약으로 대체 →
  k 축소. (전체 요약과 목차는 마지막까지 유지)
- **이미지는 최후 수단**: "화면을 직접 봐야만 답할 수 있는 질의"(색상, 배치, 표정 등)로
  판단될 때만 top 1~3 씬의 키프레임을 첨부
- **위치 배치**: 가장 관련도 높은 씬 카드를 컨텍스트 끝(질문 직전)에 배치 —
  lost-in-the-middle 완화

## 4. 긴 영상의 전체 요약: Map-Reduce

전체 요약 자체가 컨텍스트를 초과하는 경우:

1. **Map**: 챕터별로 (씬 카드 묶음 → 챕터 요약) 독립 수행 — 병렬화 가능, 각 호출은 작은 컨텍스트
2. **Reduce**: 챕터 요약들 → 전체 요약
3. 결과를 타임라인에 저장(캐시) — 질의응답 시 전역 맥락 층으로 재사용

챕터가 매우 많으면 Reduce를 트리 형태로 반복 (log 깊이).

## 5. 파이프라인 실행 전략

- **전처리(무거움, 1회)**: 씬 검출 → 캡셔닝/STT/diarization → 인덱싱 → 계층 요약.
  영상 등록 시점에 백그라운드로 수행, 결과는 영상 해시 기준 영구 캐시
- **질의(가벼움, 반복)**: 검색 → 조립 → LLM 1~2회 호출. 전처리 산출물만 사용하므로 즉답 수준
- **2-Pass 심화**: 질의로 선택된 구간에 한해 고품질 재전사·재캡셔닝·OCR을 온디맨드 수행 후
  타임라인에 증분 반영

## 6. 품질 검증 기준 (권장)

- 구간 검색: 정답 구간이 top-k에 포함되는 비율 (recall@k) — 테스트 질의 세트로 측정
- 요약: 챕터 요약에 각 챕터 핵심 이벤트 포함 여부를 체크리스트로 검증
- 토큰 효율: 질의당 평균 입력 토큰 / 원본 대비 압축률 추적
- 회귀 방지: 전처리 파라미터(씬 임계값, k, 예산 배분) 변경 시 위 지표로 비교
