# 음성(오디오) 전처리 방법론

목표: 오디오 트랙을 **"타임스탬프가 달린 정제된 전사문 + 화자 정보 + 오디오 이벤트"**로
변환하고, STT 대상 자체를 줄여 처리 시간과 토큰을 동시에 절감한다.

## 1. 음성 구간 검출 (VAD, Voice Activity Detection)

STT를 돌리기 전에 **무음·비음성 구간을 먼저 제거**한다. 조기 압축의 대표 사례.

- **도구**: Silero VAD (경량, CPU 실시간 이상), WebRTC VAD
- **효과**
  - 무음/음악 위주 구간이 많은 영상에서 STT 대상이 30~70% 감소 → 처리 시간 직결
  - Whisper 계열의 무음 구간 환각(hallucination) 방지 → 정확도 향상
- **출력**: 음성 세그먼트 목록 `[{start, end}]` — 이후 STT는 이 구간만 처리

## 2. 음성 인식 (STT)

- **도구 (로컬 기준)**: faster-whisper (CTranslate2 최적화, 원본 Whisper 대비 4배 이상 빠름),
  whisper.cpp (Apple Silicon/CPU 친화)
- **모델 크기 전략**
  - 기본: `small`/`medium` — 대부분 질의응답에 충분
  - 2-Pass: 중요 구간으로 선별된 세그먼트만 `large`로 재전사 (선택적 심화)
- **최적화**
  - VAD 세그먼트 단위 배치 처리 + 병렬화
  - 워드 타임스탬프 활성화 → 타임라인 정밀 정렬에 사용
  - 언어 자동 감지 결과 캐싱 (구간마다 재감지 방지)

## 3. 화자 분리 (Speaker Diarization)

"누가 말했는가"는 회의·인터뷰 영상 분석 정확도에 직결된다.

- **도구**: pyannote.audio, NeMo diarization (로컬 실행 가능)
- **통합**: diarization 결과(화자 구간)와 STT 세그먼트를 타임스탬프로 정렬해
  `speaker_id`를 전사문에 부여
- **비용 판단**: 화자가 1명임이 명백한 콘텐츠(강의, 내레이션)는 스킵 —
  메타데이터나 초반 샘플 분석으로 판단하는 게이트를 둔다

## 4. 비음성 오디오 이벤트 태깅

음성 외 소리도 이벤트 분석에는 중요한 신호다 (박수, 웃음, 음악 시작, 충돌음, 사이렌 등).

- **도구**: PANNs, CLAP 계열 오디오 태깅 모델 (전 구간 대신 VAD가 "비음성"으로 분류한 구간 위주)
- **출력**: `[{start, end, event: "applause", confidence: 0.91}]`
- 음악 구간은 별도 태그로 묶어 전사 대상에서 제외 (가사 전사가 필요한 경우만 예외)

## 5. 전사문 후처리 (토큰 절감의 핵심)

원시 전사문은 그대로 넣기엔 토큰 낭비가 크다.

1. **필러 제거**: "어…", "그니까", 반복 발화 제거 (정규식 + 간단한 규칙)
2. **문장 단위 병합**: 워드/조각 세그먼트를 문장 단위로 재구성, 문장별 대표 타임스탬프 유지
3. **발화 턴 병합**: 같은 화자의 연속 문장을 하나의 턴으로 묶기
   → `[화자A 12:34] 문장들...` 형태로 라인 수 대폭 감소
4. **정규화**: 숫자·단위 표기 통일 (검색 정확도 향상)

## 6. 계층적 전사 요약

영상 파이프라인과 대칭 구조:

```
발화 턴 → 씬/토픽 단위 대화 요약 → 챕터 요약 → 전체 대화 요약
```

- 토픽 전환 검출: 문장 임베딩의 유사도 변화 지점 (TextTiling 방식) 또는 영상 씬 경계와 결합
- 요약은 소형 LLM으로 전처리 단계에서 배치 생성
- 질의 시: 전체 요약 + 관련 구간의 **원문 발화 턴**(요약이 아닌 원문 — 인용·정확성 필요 시)

## 7. 처리 성능 최적화

- 오디오는 디먹싱 후 16kHz mono WAV로 정규화 → 모든 후속 모델의 공통 입력
- VAD → STT → diarization을 스트리밍 파이프라인으로 연결 (영상 처리와 완전 병렬)
- 전사·이벤트 결과를 오디오 해시 기준으로 캐싱
