# 영상(비주얼) 전처리 방법론

목표: 프레임 시퀀스를 **"의미 단위(씬) + 대표 프레임 + 텍스트 캡션"**으로 압축하여
LLM에 전달할 시각 정보의 양을 수십~수백 배 줄인다.

## 1. 샷/씬 경계 검출 (Shot & Scene Boundary Detection)

프레임을 개별로 다루지 않고 **씬을 처리 단위**로 삼는 것이 모든 최적화의 출발점.

- **방법**
  - 히스토그램/픽셀 차분 기반: PySceneDetect(`ContentDetector`), FFmpeg `scdet` 필터 — 빠르고 CPU만으로 가능
  - 임베딩 기반: 프레임 임베딩(CLIP 등) 간 코사인 거리 급변 지점 검출 — 페이드·디졸브 등 점진 전환에 강함
- **출력**: `[{scene_id, start_ts, end_ts}]`
- **최적화 포인트**
  - 저해상도(예: 320px)로 다운스케일 후 검출해도 정확도 손실 거의 없음 → 디코딩 비용 절감
  - 씬이 지나치게 잘게 쪼개지면(뮤직비디오 등) 최소 씬 길이로 병합

## 2. 적응적 키프레임 샘플링 (Adaptive Keyframe Sampling)

고정 간격(1fps 등) 샘플링은 정적인 구간에서 중복 프레임을 양산한다.

- **씬당 대표 프레임 N장** 선택 (기본 1~3장):
  - 씬 중앙 프레임 + 시각 변화량이 큰 프레임
  - 씬이 길면 시간 비례로 추가
- **중복 제거 (Deduplication)**
  - 지각 해시(pHash/dHash) 해밍 거리 또는 임베딩 유사도 임계값으로 근사 중복 프레임 폐기
  - 슬라이드 발표 영상처럼 정적인 콘텐츠는 "변화가 생긴 순간"만 남기면 압축률 극대화
- **효과**: 1시간 영상(1fps 기준 3,600장) → 씬 기반 샘플링 시 보통 100~300장 수준

### 현재 구현: `duration-adaptive-v1`

현재 03단계는 화면 변화량 기반 frame 선택 전 단계로, 씬 길이와 설정 상한만 사용하는 결정적
정책을 구현한다.

| 씬 길이 | 선택 수 |
|---:|---:|
| 8초 미만 | 1장 |
| 8초 이상 20초 미만 | 2장 |
| 20초 이상 | 3장 |

`keyframes_per_scene` 1~3을 최종 상한으로 적용한다. N장의 timestamp는
`start + duration * i / (N + 1)`의 내부 균등 지점이라 씬 끝 경계에서 다음 씬 프레임을 읽지 않는다.
기본 상한 1은 기존 중앙 프레임 동작을 유지한다. 각 frame의 순서와 수는 JSON에 보존되고 같은 씬의
caption은 timeline에서 전체 배열과 호환용 ordered summary로 함께 제공한다. 상세 계약은
[`ADR-0030`](./adr/0030-duration-adaptive-keyframes-and-scene-caption-summary.md)을 따른다.

시간 기반 frame끼리 시각적으로 같을 수 있으므로 perceptual hash 중복 제거는 다음 구현 단계다.

## 3. 프레임의 텍스트화 (Captioning)

이미지 자체를 LLM에 넣는 대신, **경량 비전 모델로 캡션을 생성해 텍스트로 전달**한다.

- 이미지 1장 ≈ 수백~수천 토큰 vs 캡션 1~2문장 ≈ 30~80 토큰
- **모델 선택 (로컬 기준)**: 경량 VLM (예: LLaVA 계열 소형, Moondream, Florence-2 등)
  — 캡셔닝은 메인 분석 LLM보다 작은 모델로 충분
- **캡션 프롬프트 설계**: "장면 묘사 + 등장 인물/객체 + 화면 내 텍스트 유무"처럼
  후속 분석에 필요한 요소를 고정 스키마로 뽑도록 지시
- **씬 캡션 통합**: 같은 씬의 프레임 캡션들을 병합해 씬당 1개의 요약 캡션 생성

## 4. 선택적 심화 분석 (Lazy / 2-Pass)

비싼 연산은 전 구간이 아니라 **필요한 씬에만** 적용한다.

| 연산 | 1차 트리거 조건 | 도구 예시 |
|---|---|---|
| OCR | 캡션에 "텍스트/자막/슬라이드" 감지 시 | PaddleOCR, Tesseract |
| 객체 검출 | 질의가 특정 객체를 언급하거나 이벤트 분석 모드일 때 | YOLO 계열 |
| 얼굴 인식/추적 | 인물 중심 질의일 때 | InsightFace 등 |
| 고해상도 재캡셔닝 | 질의 시점에 해당 씬이 top-k로 선택됐을 때 | 상위 VLM |

- 2차 패스 결과는 타임라인에 증분 병합(캐시)하여 재질의 시 재사용

## 5. 계층적 시각 요약

```
프레임 캡션 → 씬 캡션 → 챕터(씬 그룹) 요약 → 전체 시각 요약
```

- 씬 임베딩을 클러스터링하거나 시간 연속성 기준으로 챕터를 구성
- 상위 계층 요약은 소형 LLM으로 배치 생성 (전처리 단계에서 완료)
- 질의응답 시: 전체 요약(항상 포함, 소량) + 관련 씬 캡션(선별) + 필요 시 키프레임 이미지(최후 수단)

## 6. 처리 성능 최적화

- **디코딩**: 씬 검출은 저해상도 스트림으로, 키프레임 추출은 해당 타임스탬프만 시크(seek)해서 디코딩
  (FFmpeg `-ss` 입력 시크 + `-frames:v 1`)
- **병렬화**: 씬 단위로 독립 처리 가능 → 씬 목록을 워커 풀에 분배
- **하드웨어 가속**: 디코딩은 VideoToolbox/NVDEC, 추론은 GPU 배치 처리
- **캐싱**: 영상 해시 기준으로 씬 경계·캡션·임베딩을 디스크 캐시 → 재분석 시 스킵
